Fundamentos

¿Qué es un LLM?

Un modelo de lenguaje grande (LLM) es una red entrenada con enormes cantidades de texto y código, que predice el siguiente fragmento de texto (token) más probable dado el contexto.

L

Lee

Analiza archivos, historial de git, errores y documentación como contexto.

E

Escribe

Genera y edita código, tests, commits y documentación.

E

Ejecuta

Corre comandos, tests y builds a través de herramientas (tool use).

I

Itera

Lee el resultado de cada acción y ajusta el siguiente paso, en bucle.

Claude Code

¿Qué es Claude Code?

Un entorno de codificación agéntico: a diferencia de un chatbot que responde y espera, Claude Code lee archivos, ejecuta comandos, hace cambios y resuelve problemas de forma autónoma mientras vos observás, redirigís o te alejás del teclado.

  • Disponible en terminal, VS Code, JetBrains, app de escritorio y navegador
  • Explora el repo, planifica cambios en varios archivos y los implementa
  • Corre tests, lee errores y vuelve a intentar sin supervisión constante
  • Se conecta a GitHub, MCP servers y otras herramientas del equipo

“Describís lo que querés y Claude figura cómo construirlo. Explora, planifica e implementa.”

Claude Code

El flujo recomendado de trabajo

Separar la exploración y planificación de la implementación evita resolver el problema equivocado.

1

Explorar

Modo plan: Claude lee archivos y responde preguntas sin modificar nada.

2

Planificar

Pedile un plan de implementación detallado. Editalo con Ctrl+G si hace falta.

3

Implementar

Salís del modo plan: Claude codea y verifica contra su propio plan.

4

Commitear

Pedile un commit con mensaje descriptivo y, si aplica, un PR.

Fuente: code.claude.com/docs — Best practices for Claude Code
Buenas prácticas

Dale contexto específico

Claude puede inferir intención, pero no puede leer tu mente. Cuanto más preciso el pedido, menos correcciones necesitás después.

AntesDespués
Ejemplo 1“agregá tests para foo.py”“escribí un test para foo.py que cubra el caso donde el usuario está deslogueado. Evitá mocks.”
Ejemplo 2“arreglá el bug de login”“los usuarios reportan que el login falla tras expirar la sesión. Revisá el flujo en src/auth/, especialmente el refresh de tokens. Escribí un test que reproduzca el bug y después arreglalo.”

Buenas prácticas

CLAUDE.md: memoria persistente del proyecto

Un archivo que Claude Code lee al empezar cada sesión. Ejecutá /init para generar uno a partir de tu repo, y refinalo con el tiempo.

✓ Incluir

  • Comandos de bash que Claude no puede adivinar
  • Reglas de estilo distintas al default del lenguaje
  • Instrucciones de testing y test runner preferido
  • Convenciones de branches y pull requests
  • Decisiones de arquitectura específicas del proyecto

✕ Evitar

  • Cosas que Claude ya puede inferir leyendo el código
  • Documentación larga de APIs (mejor linkearla)
  • Información que cambia con frecuencia
  • Descripciones archivo por archivo del repo
  • Prácticas obvias como “escribí código limpio”
Regla práctica: por cada línea preguntate “¿si la saco, Claude comete un error?”. Si no, sacala.
Buenas prácticas

Dale a Claude una forma de verificar su trabajo

Sin un check que pueda correr, “parece terminado” es la única señal disponible. Con un check, el ciclo se cierra solo: Claude trabaja, corre el check, lee el resultado e itera.

✓

Tests

Correr la suite y pedir que arregle lo que falle.

✓

Build / lint

Un exit code que indica éxito o error de forma objetiva.

✓

Captura de pantalla

Comparar el resultado visual contra un diseño de referencia.

✓

Subagente revisor

Una segunda pasada, en contexto limpio, que audite el diff.

Fuente: code.claude.com/docs — Best practices for Claude Code
Buenas prácticas

Gestioná el context window

El contexto de Claude guarda toda la conversación: cada mensaje, archivo leído y salida de comando. El rendimiento se degrada a medida que se llena.

/clearResetea el contexto entre tareas no relacionadas.
SubagentesInvestigan en un contexto separado y reportan un resumen.
/rewindRestaura conversación, código o ambos a un checkpoint anterior.
Regla de 2 correccionesSi corregiste lo mismo dos veces, hacé /clear y escribí un mejor prompt inicial.

Señales de que el contexto está saturado

  • Claude “olvida” instrucciones dadas antes
  • Empieza a cometer más errores
  • Repite pasos ya corregidos
  • Mezcla información de tareas distintas
Fuente: code.claude.com/docs — Best practices for Claude Code

Claude en general

Buenas prácticas de prompting

Los mismos principios aplican fuera de Claude Code: en claude.ai, la API o cualquier integración.

Sé claro y específico

Detallá formato, tono, audiencia y restricciones en vez de dar por sentado que Claude las adivina.

Dale ejemplos

Mostrar 2-3 ejemplos de entrada/salida deseada mejora mucho la consistencia.

Pedí razonamiento paso a paso

Para tareas complejas, pedir que piense antes de responder mejora la calidad.

Usá etiquetas XML

Estructurar el prompt con <contexto>, <tarea>, <formato> ayuda a Claude a separar partes.

Especificá extensión y formato

Indicá si querés una lista, una tabla, un párrafo o una extensión máxima.

Iterá el prompt

Tratalo como código: probá, ajustá, y guardá lo que funciona para reusar.

Tokens

¿Qué es un token?

La unidad mínima de texto que procesa un modelo: no es una palabra ni una letra, sino un fragmento intermedio.

  • En inglés, 1 token ≈ 4 caracteres ≈ ¾ de palabra
  • El input (tu prompt + archivos + historial) y el output (la respuesta) se miden en tokens
  • El “thinking” o razonamiento extendido también consume y se cobra como tokens de salida
  • Los precios de la API se publican en USD por millón de tokens (MTok)
Ejemplo rápido

“Claude Code lee archivos”

≈ 6-7 tokens

Un repo completo leído como contexto puede sumar decenas o cientos de miles de tokens fácilmente.

Reasoning effort

Niveles de effort en Claude

El parámetro effort controla cuántos tokens usa Claude para responder: pensamiento, texto y llamadas a herramientas.

NivelQué haceCaso de uso típico
lowMáxima eficiencia; ahorro de tokens notable con algo de reducción de capacidad.Tareas simples, alto volumen o subagentes.
mediumEnfoque equilibrado, ahorro moderado de tokens.Tareas agénticas que buscan balance costo/velocidad.
high (default)Capacidad alta. Es el comportamiento si no se cambia el parámetro.Razonamiento complejo, coding difícil, tareas agénticas.
xhighCapacidad extendida para trabajo de largo horizonte.Coding y agentes de más de 30 min, presupuestos de millones de tokens.
maxMáxima capacidad posible, sin límite de gasto de tokens.Problemas realmente de frontera.

Otros LLM

¿Qué significa “abierto” en un LLM?

“Open weight” no es lo mismo que “open source”: normalmente se publican los parámetros entrenados, pero no siempre el código ni los datos de entrenamiento.

DimensiónModelos abiertos (DeepSeek, Qwen, GLM, Kimi…)Modelos cerrados (Claude, GPT, Gemini)
Acceso a los pesosDescargables (ej. Hugging Face)No se publican
Self-hostingPosible, con tu propia infraestructuraNo, solo vía API del proveedor
Fine-tuning propioPosible sobre los pesos originalesLimitado a lo que ofrezca el proveedor
Costo por tokenGeneralmente más bajoGeneralmente más alto
Soporte y actualizacionesA tu cargo (o de quien te hostee)Incluido por el proveedor
Licencia típicaMIT / Apache 2.0 (la mayoría)Términos de servicio comerciales

Cuándo conviene cada opción

Modelos abiertos

  • Control total de tus datos: podés self-hostear on-prem o en tu propia nube
  • Costo por token mucho menor, sobre todo a gran volumen
  • Podés fine-tunear el modelo sobre tus propios datos
  • Sin dependencia de un solo proveedor comercial

Claude

  • Cero infraestructura propia que mantener o escalar
  • Herramientas maduras: Claude Code, MCP, computer use
  • Soporte, SLA y actualizaciones incluidas por Anthropic
  • Controles de seguridad y cumplimiento a nivel empresarial
Otros LLM

¿Se pueden usar en Claude Code?

Respuesta corta: no de forma nativa. Claude Code está construido y optimizado específicamente para los modelos Claude.

El soporte “de terceros” de Claude Code (Terminal y VS Code) es para exponer los propios modelos Claude a través de Amazon Bedrock, Google Vertex AI, u otro endpoint compatible con la API de Anthropic, no para correr DeepSeek, Qwen o GLM dentro de Claude Code.

Si tu equipo quiere trabajar con un modelo abierto en un flujo agéntico, lo normal es usar la CLI o el plan de coding propio de ese proveedor (por ejemplo, el GLM Coding Plan de Z.ai o el CLI de Kimi), u otra herramienta agnóstica de modelo, no Claude Code.

Prompt caching y context editing

Reutilizar el contexto ya procesado (CLAUDE.md, codebase, ejemplos) evita pagarlo entero en cada turno.

Recorta o resume automáticamente resultados viejos de herramientas para que no acumulen espacio en el contexto sin aportar valor a la tarea actual. Complementa a /clear y /compact.

Temas avanzados

Seguridad: prompt injection en agentes

Instrucciones maliciosas escondidas en contenido que el agente lee (una página web, un email, un issue) que el modelo puede confundir con órdenes legítimas del usuario.

Por qué importa más ahora

Un chatbot que solo devuelve texto tiene impacto limitado si lo engañan. Un agente con acceso a herramientas, que puede escribir archivos, mandar mensajes o ejecutar comandos, puede convertir esas instrucciones en acciones reales.

Cómo mitigarlo

  • Tratar todo contenido externo como dato, nunca como instrucción
  • Mínimo privilegio: solo las herramientas y permisos que la tarea necesita
  • Confirmación explícita antes de acciones irreversibles o sensibles
  • Revisar y loguear qué hizo el agente, no solo qué te reportó
